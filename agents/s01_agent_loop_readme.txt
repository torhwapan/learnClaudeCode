知识点：
一， 关于 user, system,assistent,tool
这三个角色分别代表对话中的不同“人设”，API 会根据角色区分指令、提问和历史回复。
1. system（系统/设定）
*   作用：设定 AI 的人设、规则、背景或全局指令。
*   使用时机：放在消息列表的最前面，通常只需设置一次。
*   示例：{"role": "system", "content": "你是一个 Python 专家，只回答代码问题。"}
2. user（用户）
*   作用：模拟人类发出的提问、指令或输入内容。
*   使用时机：你向 AI 发送新问题时，追加到历史消息的末尾。
*   示例：{"role": "user", "content": "请用 Python 写一个冒泡排序。"}
3. assistant（助手）
*   作用：记录 AI 之前的回复，或者用来提供示例回答（Few-shot）。
*   使用时机：
    *   在多轮对话中：AI 每次回复后，把回复内容存为 assistant 角色，以便 AI 能“记住”上下文。
    *   在示例中：你可以手动写一段假回复来教 AI 按什么格式回答。
*   示例：{"role": "assistant", "content": "好的，这是冒泡排序的代码..."}
4，tool
   补充：阿里百炼平台调用tool返回的结果，再传入大模型时，role角色用‘tool’，其他模型可能会用‘user’或者‘assistant’，用‘role’可能可以更好区分数据来源

二， 关于不同大模型的调用
不同大模型调用的入参、回参会有些差别，包括TOOLS的定义也会有区别。


实操：
s01_agent_loop.py 代码使用阿里百炼的大模型作为底模，现在成功跑通，可尝试的用例eg:
eg1: "帮我看看我当前文件目录下，有几个文件呢?"
eg2: "帮我看看我当前文件目录下，各文件的大小是多少？"

eg1执行时， 大模型首先给出的Linux的原生的 'ls' 'wc'命令，执行失败后，将错误结果回传给大模型，大模型再次给出的才是Windows的'dir'命令。
